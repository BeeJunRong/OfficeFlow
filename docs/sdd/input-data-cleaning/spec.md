# 输入数据清理模块需求规格说明书

| 字段 | 值 |
|------|-----|
| 模块名称 | 输入数据清理模块（Input Data Cleaning Module） |
| 版本 | v1.0 |
| 创建日期 | 2026-10-14 |
| 状态 | 待评审 |

---

## 1. 概述

### 1.1 背景

OfficeFlow 会议纪要提取流程当前对输入文本仅做首尾 `strip()` 处理（`meeting_minutes.py:run()` 第 59 行），未对文本内部的格式噪声进行清理。用户粘贴的会议记录常携带多余空格、连续空行、不可见字符（零宽字符、BOM）、混合换行符（`\r\n` / `\r`）等格式噪声，这些噪声会干扰结构化抽取和零编造校验的准确性。

### 1.2 目的

在会议纪要提取之前对输入文本进行数据清理，去除格式噪声，提高抽取质量和校验准确性，同时严格保证原文实体字符串（人名、日期、地点等）不被破坏，确保零编造校验（`validate_minutes` 的字符串包含检查）仍能正确匹配。

### 1.3 范围

- **范围内**：对 `input_text` 字符串执行纯文本格式清理，输出清理后的字符串。
- **范围外**：不负责语义理解、不负责任务路由、不负责模板前缀剥离（已由 `strip_template_prefix` 处理）、不负责落库（落库仍存原始 `req.input_text`）。

## 2. 功能需求

### FR-DC-01: 去除多余空格

**描述**：将文本中连续多个空格（U+0020）合并为单个空格。

**验收标准**：
- **WHEN** 输入文本包含连续两个或更多空格 **THEN** 系统应将其合并为单个空格
- **WHEN** 输入文本中空格位于行首或行尾 **THEN** 系统应保留该行非首尾位置的必要单个空格
- **WHEN** 输入文本中单个空格 **THEN** 系统应保持不变

**约束说明**：行内缩进（如代码块前的空格）不在此需求范围内；本需求针对的是行内连续多空格的合并。

### FR-DC-02: 去除多余空行

**描述**：将文本中连续多个空行合并为单个空行。

**验收标准**：
- **WHEN** 输入文本包含连续两个或更多空行 **THEN** 系统应将其合并为单个空行
- **WHEN** 输入文本中单个空行 **THEN** 系统应保持不变
- **WHEN** 输入文本中不存在连续空行 **THEN** 系统应保持原文行结构不变

### FR-DC-03: 去除不可见字符

**描述**：去除文本中的不可见字符，包括零宽字符（U+200B、U+200C、U+200D）、零宽空格（U+FEFF / BOM）、不换行空格（U+00A0）以外的控制字符（U+0000~U+001F 中除 `\t`、`\n`、`\r` 外的字符）。

**验收标准**：
- **WHEN** 输入文本包含零宽字符（U+200B / U+200C / U+200D） **THEN** 系统应将其去除
- **WHEN** 输入文本包含 BOM 字符（U+FEFF） **THEN** 系统应将其去除
- **WHEN** 输入文本包含控制字符（U+0000~U+0008、U+000B、U+000C、U+000E~U+001F） **THEN** 系统应将其去除
- **WHEN** 输入文本包含制表符（U+0009 / `\t`） **THEN** 系统应保持不变
- **WHEN** 输入文本包含换行符（U+000A / `\n`） **THEN** 系统应保持不变（由 FR-DC-04 统一处理）
- **WHEN** 输入文本包含回车符（U+000D / `\r`） **THEN** 系统应保持不变（由 FR-DC-04 统一处理）

### FR-DC-04: 统一换行符

**描述**：将文本中的 Windows 换行符（`\r\n`）和旧 Mac 换行符（`\r`）统一为 Unix 换行符（`\n`）。

**验收标准**：
- **WHEN** 输入文本包含 `\r\n` **THEN** 系统应将其替换为 `\n`
- **WHEN** 输入文本包含单独的 `\r`（不伴随 `\n`） **THEN** 系统应将其替换为 `\n`
- **WHEN** 输入文本仅包含 `\n` **THEN** 系统应保持不变

### FR-DC-05: 去除首尾空白

**描述**：去除文本首尾的空白字符（空格、制表符、换行符等）。

**验收标准**：
- **WHEN** 输入文本首部包含空白字符 **THEN** 系统应将其去除
- **WHEN** 输入文本尾部包含空白字符 **THEN** 系统应将其去除
- **WHEN** 输入文本首尾无空白字符 **THEN** 系统应保持不变

### FR-DC-06: 保留原文实体

**描述**：清洗后的文本必须保留所有原文中的人名、日期、地点等实体字符串，确保 `validate_minutes` 的字符串包含检查（`value not in source_text`）仍能正确匹配。

**验收标准**：
- **WHEN** 原文包含人名实体（如"张三"、"王敏"） **THEN** 清洗后文本必须完整保留该人名字符串
- **WHEN** 原文包含日期实体（如"2026年10月9日"、"10月14日"） **THEN** 清洗后文本必须完整保留该日期字符串
- **WHEN** 原文包含地点实体（如"第一会议室"、"线上"） **THEN** 清洗后文本必须完整保留该地点字符串
- **WHEN** 原文包含有意义的标点符号（如"："、"，"、"。"、"、"） **THEN** 清洗后文本必须保留该标点符号
- **WHEN** 清洗后文本传入 `validate_minutes(minutes, cleaned_text)` **THEN** 原文中存在的实体值必须仍能在 `cleaned_text` 中通过字符串包含检查

## 3. 非功能需求

### NFR-DC-01: 纯函数无副作用

**描述**：数据清理函数必须是纯函数，不修改输入参数，不依赖外部状态，不产生任何副作用。

**验收标准**：
- **WHEN** 对同一输入多次调用清理函数 **THEN** 每次返回的结果必须完全相同
- **WHEN** 调用清理函数 **THEN** 输入参数对象本身不被修改

### NFR-DC-02: 不依赖外部服务

**描述**：数据清理模块不依赖任何外部服务（LLM、网络、数据库等），仅使用标准库或纯本地计算。

**验收标准**：
- **WHEN** 在无网络、无 LLM、无数据库的环境中 **THEN** 数据清理功能必须正常工作

### NFR-DC-03: 确定性

**描述**：相同输入永远产生相同输出，不受时间、环境、随机数等因素影响。

**验收标准**：
- **WHEN** 对同一输入在不同时间、不同进程调用清理函数 **THEN** 输出必须完全一致

### NFR-DC-04: 幂等性

**描述**：对已清洗的文本再次清洗，结果不变。

**验收标准**：
- **WHEN** 对输入文本执行清理函数得到结果 R1，再对 R1 执行清理函数得到 R2 **THEN** R1 必须等于 R2

### NFR-DC-05: 性能

**描述**：处理 100KB 文本应在 100ms 内完成。

**验收标准**：
- **WHEN** 输入文本大小为 100KB **THEN** 清理函数执行时间应不超过 100ms

## 4. 约束条件

### CON-DC-01: 实体保留约束

清洗后的文本必须保留所有原文中的人名、日期、地点等实体字符串。清理操作仅针对格式噪声（空格、空行、不可见字符、换行符），不得对文本中的语义内容做任何增删改。

### CON-DC-02: 标点符号保留约束

不能删除有意义的标点符号（包括但不限于中文标点"：""，""。""、""；""！"""？"和英文标点":" "," "." ";" "!" "?"）。

### CON-DC-03: 语义不变约束

清理操作不能改变文本的语义内容。清理仅限于格式层面的规范化（空格合并、空行合并、不可见字符去除、换行符统一、首尾空白去除），不得对文字内容做任何语义层面的修改。

### CON-DC-04: 与 _normalize_date_breaks 不冲突约束

清洗步骤不应与 `rule_based_extract` 内部的 `_normalize_date_breaks`（修复日期跨行断开，如将 "10月9\n日" 修复为 "10月9日"）产生冲突。数据清理模块应只处理格式噪声，不处理日期跨行修复（该职责属于 `_normalize_date_breaks`），两者可串联执行且执行顺序不影响最终结果。

### CON-DC-05: 清洗时机约束

数据清理应在 `strip_template_prefix`（模板前缀剥离）之后、`extract_meeting_minutes`（结构化抽取）之前执行。清理后的文本同时用于抽取和校验（`validate_minutes` 的 `source_text` 参数应传入清理后的文本）。

### CON-DC-06: 落库保留原文约束

落库时仍存储原始 `req.input_text`，不存储清理后的文本。清理后的文本仅用于抽取和校验流程。

## 5. 验收标准

### AC-DC-01: 功能需求测试覆盖

所有功能需求（FR-DC-01 ~ FR-DC-06）都有对应的单元测试用例，且全部通过。

### AC-DC-02: 实体保留校验兼容性

清洗后人名、日期、地点等实体仍能被 `validate_minutes` 正确匹配（即 `value in cleaned_text` 为 True）。使用现有 13 例合成样本验证：对每个样本清洗后执行完整抽取 + 校验流程，校验结果中的回退项（corrections）不应因清洗而增加。

### AC-DC-03: 幂等性测试

对任意输入文本，连续执行两次清理函数，两次结果必须完全相同。

### AC-DC-04: 性能测试

对 100KB 文本执行清理函数，耗时不超过 100ms。

### AC-DC-05: 现有测试回归

现有测试套件（`test_fr01.py`、`test_router.py` 等）在引入数据清理模块后仍全部通过，不产生回归。

### AC-DC-06: 空输入处理

**WHEN** 输入为空字符串或纯空白字符串 **THEN** 清理函数应返回空字符串，不抛出异常。

## 6. 术语表

| 术语 | 定义 |
|------|------|
| 格式噪声 | 文本中不影响语义但影响程序处理的字符，包括多余空格、多余空行、不可见字符、混合换行符等 |
| 零宽字符 | Unicode 中的不可见字符，包括 U+200B（零宽空格）、U+200C（零宽非连接符）、U+200D（零宽连接符） |
| BOM | Byte Order Mark，字节顺序标记，Unicode 中为 U+FEFF |
| 幂等性 | 对函数输出再次应用该函数，结果不变，即 f(f(x)) = f(x) |
| 零编造校验 | `validate_minutes` 中通过 `value not in source_text` 检查抽取值是否在原文中出现，未出现则回退为"待确认" |
| 实体字符串 | 原文中具有语义意义的人名、日期、地点等字符串片段，是零编造校验的匹配对象 |
