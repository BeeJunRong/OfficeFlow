## 未发布（2026-10-22）：跨轮产物复用 + 原文行号 + 邮件收件人修复

### 问题（真实会话复现：纪要 → "接着做周报" → "帮我发送邮件"）

1. **跨轮产物丢失**：第 2 轮"接着帮我整理成周报"时，后端不知道上一轮纪要（history 只带文本摘要），
   周报的"下周计划"为空；第 3 轮邮件按空纪要派生，收件人为 0 位，界面没有可填邮箱的收件人输入框。
2. **原文依据无行号**：周报/纪要只给出证据片段，用户要求定位到原始输入的第几行。
3. **邮件兜底缺失**：收件人为空时直接 `return`，没有手动补录入口。

### 修复

- **跨轮产物注入**（`app/main.py`）：前端 history 的 assistant 条目新增 `session_id`；
  `/api/generate` 启动前从 SQLite 恢复上一轮主产物（纪要/周报/邮件）并注入 `AgentState`，
  按类型放回 `structured_result / weekly_report / email_draft`。ReAct 工具与 Skill 派生均直接复用真实产物。
- **ReAct 提示**：检测到已注入产物时，system prompt 明确"直接派生，不要重新 extract_fields 覆盖"。
- **原文行号**：
  - `ActionItem` / `WeeklyReportItem` 新增 `evidence_line`（1-based）；
  - `validate` 节点以**原始输入**（`raw_input_text`，而非清理后文本）定位证据行号，
    兼容空白差异（去空白逐行兜底匹配）；
  - 周报构建同时为"本周进展（决定）"与"下周计划（待办）"计算行号；
  - 纪要表格与周报 Markdown/前端表格统一显示 `第N行：原文片段`。
- **邮件 UI 兜底**：收件人为 0 时不再直接返回，提供姓名/邮箱/内容手动补录输入框；
  自动分析出收件人时保持原有逐人邮箱输入 + 勾选发送。

### 验证

- `tests/test_react.py` 新增 3 条：原文行号（纪要）、周报行号（API）、跨轮纪要→周报→邮件三轮派生。
- `pytest tests -q` → **131 passed**。
- 跨轮回归断言：第 2 轮周报 `next_plan` 负责人为阿敏/小李且行号非空；第 3 轮邮件收件人为 2 位
  （来自纪要负责人去重）、邮箱全部留空待手填、Markdown 正常产出。

## 未发布（2026-10-22）：自动识别（ReAct）数据流修复 —— 多步纪要+周报可产出

### 问题

自动识别模式下输入"帮我做会议纪要接着做一份周报"时，系统反复出现：

```text
MeetingMinutes 反序列化仍失败：action_items.0.task Field required
input_value={'content': '...', 'deadline': '待确认'}
```

validate 连续失败 4 次耗尽迭代，最终没有生成结果（前端显示空结果）。

### 根因（框架逻辑）

1. **工具间数据靠 LLM 转述**：`extract_fields` 只把数量摘要回填给模型，完整结构化结果留在状态里；模型调用 validate 时凭记忆重写 `minutes`，键名丢失（`task` 写成 `content`）或内容截断。
2. **注入条件过窄**：`_inject_context` 仅在参数为空时注入真实产物，非空但错误的参数被直接放行。
3. **缺少兜底渲染**：模型漏调 `render_*` 或迭代耗尽时，系统不会用已有结构化结果生成 Markdown。
4. **规则引擎昵称缺口**：口语样本中的"阿敏 / 小李 / 张哥"不在姓氏表，逗号分隔的第二条待办因识别不到负责人被丢弃。

### 修复

- **数据传递改为状态机权威**：`validate / render_* / build_*` 的输入一律从 `accumulated/state` 注入并覆盖，LLM 只决定"调用哪个工具"，不负责搬运数据；`source_text` 始终使用系统清理后的本轮原文。
- **反序列化归一化**：`task/content/item/action/中文键名`、`task=None`、字符串条目均可容错转成 `ActionItem`，不再因键名差异校验失败。
- **兜底渲染**：新增 `_ensure_outputs`，按已产出的 `structured_result / weekly_report / email_draft` 确定性补齐各产物 Markdown；多步时 `task_type` 取首个产物，`routed_by` 标记为 `react`。
- **规则引擎增强**：新增口语昵称模式（阿敏/老王/小李/张哥/王老师）与误报停用词；逗号分隔的多条待办按负责人边界正确拆分。
- 抽取工具摘要附带待办要素（事项/负责人/截止），便于模型规划是否派生周报/邮件。

### 验证

- 新增 `tests/test_react.py` 6 条：错误形状 payload、多步纪要+周报、漏调 render 兜底、部分渲染补齐、校验使用系统原文、归一化形状。
- `pytest tests -q` → **128 passed**。
- API 端到端（自动识别 + 真实 LLM 抽取）：返回 `meeting_minutes` + `weekly_report` 双产物，两段 Markdown 均非空，待办与周报计划字段正确，工具日志无 failed。

## 未发布（2026-10-16）：统一输入框与发送闪跳修复 + 输入数据清理模块

### 交互调整

- 首页居中与对话后底部固定共用一个 Components v2 输入组件，替代旧版首页 textarea / 对话页 `st.chat_input` 两套入口。
- 圆角多行输入框自适应高度；底栏左侧为“会议纪要 / 周报整理 / 邮件草稿 / 网页整理 / 自动识别”五个胶囊标签，窄屏横向滚动；右侧固定“↑”发送按钮。
- 标签选择任务类型，仅在内容为空时填入提示词；Enter 发送、Shift + Enter 换行，兼容中文输入法；空内容禁用发送。发送后清空，处理中禁用重复提交，结果返回后恢复输入。
- 原有生成、路由、编辑、派生、导出与邮件业务逻辑保持不变。运行依赖为 `streamlit>=1.51`；Node.js 仅用于执行新增 JavaScript 回归测试。

### 输入数据清理模块（FR-DC）

- 新增 `app/cleaning.py`：在会议纪要提取前对输入文本进行格式清理（统一换行符 `\r\n`/`\r` → `\n`、去除不可见字符如零宽/BOM/控制字符、压缩多余空格与空行、保留首尾空白语义），同时严格保留原文实体字符串（人名、日期、地点、标点等），确保零编造校验（`validate_minutes` 的字符串包含检查）仍能正确匹配。
- 新增 `tests/test_cleaning.py`：43 条测试，覆盖功能需求 FR-DC-01~06、非功能需求 NFR-DC-01~05、约束 CON-DC-01~04、验收标准 AC-DC-01~06（含 100KB 文本性能基准 ≤100ms）。
- 工作流变更：`app/graph.py` 的 `execute_node` 在调用 Skill 前先调用 `clean_input_text` 清理输入。

### 闪跳原因与修复

旧实现虽然 key 固定，但组件位于动态消息列表之后，首轮切换和消息追加改变了其 Streamlit delta path，引起卸载重建；结果逐步展示还会延迟组件重新挂载。与此同时，动画 `bottom` 并切换内边距容易造成布局跳变。

现在将组件放在配置入口和动态消息区之前，固定渲染位置与 key。始终使用相同定位和内边距，以 `.docked` 控制 `transform` 过渡。本地清空内容后先启动过渡，再通知 Python 添加消息；服务端状态回传不复位已开始的过渡。标签节点也持续复用，消息区按输入框实际高度留出底部空间。

### 验证记录

- 2026-10-16：Python 全量测试 **121 passed**，包含 `tests/test_composer.py`（1 条，覆盖无对话、1 轮、3 轮和新建对话时挂载位置与组件 ID 一致）、`tests/test_cleaning.py`（43 条，覆盖输入数据清理功能/非功能/约束/验收）及其余测试（test_fr01 12 + test_router 9 + test_export_retry 6 + test_multiskill 21 + test_web_summary 7 + test_config 22）。
- `node --test tests/frontend/composer.test.mjs`：**1 passed**，覆盖连续三次发送、清空先于通知、DOM 复用、处理中与恢复状态、草稿保留和新对话复位。
- 浏览器检查：首条发送、结果返回、连续第二次发送均保持同一输入框节点。自动化结构和时序测试不能替代逐帧视觉验收；复核步骤见[评测计划 §12](评测计划.md#12-输入框交互与过渡回归fr-05)。

## v1.5.0（2026-10-14）：Web 配置面板（选模型 + 填 Key，无需命令行）

### 新增能力

- **页面最顶部右对齐的「⚙️」配置入口**（`st.columns([8, 1])`：空列 + 右列，位于任何标题之前，视觉上紧贴 Streamlit 工具栏的 Deploy 按钮下方），用户不用碰命令行即可完成配置：
  - **核心**：选服务商（DeepSeek / 通义千问 / 本地 Ollama / OpenAI / 自定义）→ 自动带出 Base URL 与模型名 →
    填 API Key → **🔌 测试连接**（真实请求验证，不必先保存）→ 💾 保存。
  - **进阶**：抽取引擎（LangExtract 开关）、邮件发送（总开关 + SMTP 全套）、应用与文件（后端地址/导出目录/数据库路径）。
- **尽量立即生效**：模型配置写入后重置 LLM 单例，**无需重启后端**；
  仅"导出目录 / 数据库路径"需重启（面板会明确提示并给出命令）。

### 安全设计

| 约定 | 说明 |
|------|------|
| 密钥永不回显 | `GET /api/config` 只返回掩码（如 `sk-934••••••839b`），明文不出后端 |
| 白名单 | 仅 `CONFIG_FIELDS` 登记的 16 个键可写；`PATH` 等一律 400 拒绝 |
| 空值 = 不修改 | 表单留空不会抹掉已配置的 Key；清空需显式勾选 |
| 类型校验 | int / bool / URL 三类做写入前校验，避免写坏 `.env` |
| 保留原文件 | 更新是**原地改行**，`.env` 里的注释与顺序全部保留 |

### 新增端点

| 端点 | 说明 |
|------|------|
| `GET /api/config` | 读取配置（密钥掩码）+ 服务商预设 + 当前状态 |
| `POST /api/config` | 保存到 `.env` 并同步进程环境变量；返回需重启的项 |
| `POST /api/config/test` | 模型连通性测试，可传未保存的值（先测再存） |

### 顺带修复的两个缺陷

1. **`stop` 在 PID 被系统复用时失效**：原逻辑只看 PID 文件，遇到"记录的 PID 已被复用"
   就直接放弃且**不回退到端口占用者**，导致服务停不掉。
   → 改为**以端口占用者为权威目标**的三态判定（match / mismatch / unknown）：
   能读到命令行时严格校验，读不到时对 python 进程按端口放行并告警。
2. **布尔配置默认值被静默改写**：`.env` 中未设置的布尔项（如 `OFFICEFLOW_SMTP_TLS`，文档默认 `1`）
   在面板里显示为"未勾选"，一保存就会被写成 `0`。
   → 新增 `_cfg_bool()`，未设置时回落到字段默认值。

### 已知限制

- 配置面板保存的是**本机 `.env`**，不含多用户隔离与鉴权 —— 定位是本地单用户工具（与 Q-02 适用范围一致）。

## v1.4.0（2026-10-14）：多 Skill 编排（理解 C）+ 周报整理 + 邮件草稿

### 新增能力

- **多 Skill 派生（FR-06，理解 C）**：会议纪要完成后给出"可继续生成"的建议按钮，
  **用户点击才执行**；派生**复用源会话结构化结果**，不重新抽取。
  - 只提供有数据依据的方向：会议纪要 →（邮件草稿 / 周报整理）；周报 → 邮件草稿。
  - **网页整理不参与派生**（需 URL 作输入，会议记录里没有）；**邮件草稿是终端产物**（防循环）。
- **周报整理（FR-02，P1 → 正式实现）**：决定 → 本周进展；待办 → 下周计划；
  负责人/截止日期缺失的条目进"风险与待确认"清单；计划条目保留原文 evidence。
- **邮件草稿（FR-03，P1 → 正式实现）**：发件人（本人）+ 发送协议 + 收件人列表，
  收件人**由纪要中的负责人去重生成**，姓名旁边是**用户手填的邮箱**与生成的内容，逐封独立"发送"开关。
- **发送协议**：`draft_only`（默认，只出草稿）/ `mailto` / `smtp`（四重闸门后才行）。

## v1.2.0（2026-10-13）：ChatGPT 风格对话式前端重构

### 交互形态变更（用户需求）

- **空状态**：页面中央只有一个搜索框 + 四个任务提示按钮 + 「自动识别」，类似 ChatGPT 官网首页；不再有传统表单式布局。
- **提交后**：搜索框沉到页面底部固定（`st.chat_input`），中央区域变成对话流，后续多轮输入都在底部进行。
- **执行过程可见**：每一轮助手回复中，逐步展示 Agent 调用了什么工具——
  `识别任务类型（Skill 路由）→ 结构化抽取（日期/主题/决定/待办）→ 零编造校验 → Markdown 生成`，
  每个步骤以状态条（✅/❌ + 工具名 + 时间戳 + 详情）呈现，首次渲染时逐个落定，之后静态展示。
  会议纪要 / 周报整理 / 邮件草稿 / 网页整理四种任务走同一套可视化流程。
- **多轮对话**：每轮结果独立编辑、独立导出/重试；顶部提供「新建对话」。
- **任务锁定**：对话模式中提示按钮常驻输入框上方，点击即锁定下一轮的 `task_type`（显式点击优先，100% 不误路由），也可切回「自动识别」。
- 追问路径（无法确定任务类型）同样先展示路由步骤，再提示用户点选任务类型。

### 后端配套变更

### 变更文件

### 后端（FastAPI + LangGraph + Pydantic）

- **API 端点**（`app/main.py`）：
  - `POST /api/generate`：生成结构化纪要；空输入返回 400 阻止。
  - `POST /api/export`：用户显式点击触发导出 `.md`（Q-02）；支持测试环境受控失败注入。
  - `POST /api/retry`：重试上一次失败的导出。
  - `GET /api/status/{session_id}`：查询工具调用状态与导出记录（验收证据）。
  - `GET /api/download`：下载导出文件（限 exports 目录，防路径穿越）。
- **Agent 工作流**（`app/graph.py`）：LangGraph 状态图 `route → execute`；导出不在图内执行。
- **FR-00 分层路由**（`app/router.py`）：显式点击锁定（100%）→ 指令区（≤16 字符短指令）关键词 → LLM 意图分类兜底（置信度 <0.7 追问，不静默路由）；正文关键词不触发路由（T4）；LLM 不可用时降级为提示用户选择任务类型。同时负责剥离前端模板前缀（只匹配祈使句模板，不误伤正文中"待办："等冒号）。
- **FR-01 会议纪要 Skill**（`app/skills/meeting_minutes.py`）：抽取会议日期/主题/关键决定/待办（事项/负责人/截止日期/原文证据），缺失值填充"待确认"，渲染 Markdown。
- **零编造校验**（`app/validate.py`）：输出的日期/负责人必须有原文依据（含"10月12日"+会议年份 → "2026-10-12" 的合法标准化），否则强制回退"待确认"（guardsrails §2）。
