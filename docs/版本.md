## v0.2.0（2026-10-13）：ChatGPT 风格对话式前端重构

### 交互形态变更（用户需求）

- **空状态**：页面中央只有一个搜索框 + 四个任务提示按钮 + 「自动识别」，类似 ChatGPT 官网首页；不再有传统表单式布局。
- **提交后**：搜索框沉到页面底部固定（`st.chat_input`），中央区域变成对话流，后续多轮输入都在底部进行。
- **执行过程可见**：每一轮助手回复中，逐步展示 Agent 调用了什么工具——
  `识别任务类型（Skill 路由）→ 结构化抽取（日期/主题/决定/待办）→ 零编造校验 → Markdown 生成`，
  每个步骤以状态条（✅/❌ + 工具名 + 时间戳 + 详情）呈现，首次渲染时逐个落定，之后静态展示。
  会议纪要 / 周报整理 / 邮件草稿 / 网页整理四种任务走同一套可视化流程。
- **多轮对话**：每轮结果独立编辑、独立导出/重试；顶部提供「新建对话」。
- **任务锁定**：对话模式中提示按钮常驻输入框上方，点击即锁定下一轮的 `task_type`（显式点击优先，100% 不误路由），也可切回「自动识别」。
- 追问路径（无法确定任务类型）同样先展示路由步骤，再提示用户点选任务类型。

### 后端配套变更

- `app/graph.py`：路由节点（`route_node`）开始写入工具日志——路由成功记录 `task_type` 与路由方式（explicit/keyword/llm），路由失败（低置信度/无分类器）记录失败原因，前端过程展示因此覆盖完整链路。

### 变更文件

| 文件 | 变更 |
|------|------|
| `frontend/app.py` | 完全重写：空状态居中搜索框 → 对话模式沉底输入，工具步骤逐步呈现，多轮结果编辑/导出 |
| `app/graph.py` | `route_node` 增加工具日志（route 成功/失败） |

### 验证

- `pytest tests/`：20 passed（后端行为不回归）。
- Streamlit AppTest 交互冒烟（连真实后端）：任务按钮锁定 → 提交 → 4 个工具步骤渲染 → 结果编辑框出现 → 「导出 .md」成功 → 第二轮 `chat_input` 对话正常，全程无前端异常。

## v0.1.0（2026-10-12）：FR-01 会议纪要最小可用版本

按 `docs/` 全部架构与开发文档实现首版 P0 范围（单 Agent + 多工具）。

### 后端（FastAPI + LangGraph + Pydantic）

- **API 端点**（`app/main.py`）：
  - `POST /api/generate`：生成结构化纪要；空输入返回 400 阻止。
  - `POST /api/export`：用户显式点击触发导出 `.md`（Q-02）；支持测试环境受控失败注入。
  - `POST /api/retry`：重试上一次失败的导出。
  - `GET /api/status/{session_id}`：查询工具调用状态与导出记录（验收证据）。
  - `GET /api/download`：下载导出文件（限 exports 目录，防路径穿越）。
- **Agent 工作流**（`app/graph.py`）：LangGraph 状态图 `route → execute`；导出不在图内执行。
- **FR-00 分层路由**（`app/router.py`）：显式点击锁定（100%）→ 指令区（≤16 字符短指令）关键词 → LLM 意图分类兜底（置信度 <0.7 追问，不静默路由）；正文关键词不触发路由（T4）；LLM 不可用时降级为提示用户选择任务类型。同时负责剥离前端模板前缀（只匹配祈使句模板，不误伤正文中"待办："等冒号）。
- **FR-01 会议纪要 Skill**（`app/skills/meeting_minutes.py`）：抽取会议日期/主题/关键决定/待办（事项/负责人/截止日期/原文证据），缺失值填充"待确认"，渲染 Markdown。
- **零编造校验**（`app/validate.py`）：输出的日期/负责人必须有原文依据（含"10月12日"+会议年份 → "2026-10-12" 的合法标准化），否则强制回退"待确认"（guardsrails §2）。
- **抽取双引擎**（`app/tools/extract_fields.py` + `app/llm.py`）：配置 `OFFICEFLOW_MODEL_API_KEY` 时走 OpenAI 兼容协议（默认 DeepSeek，可切换 Qwen/Ollama 等）；无 Key 时确定性规则引擎离线降级（评测计划 §11 的本地快速迭代路径），工具日志标注降级。
- **Markdown 导出工具**（`app/tools/export_markdown.py`）：原子写入（重试成功不产生重复文件）、文件名安全清洗、受控失败注入。
- **占位 Skill**（`app/skills/placeholders.py`）：FR-02 周报整理 / FR-03 邮件草稿 / FR-04 网页整理返回"P1 开发中"（proposal §4）。
- **SQLite 工具日志**（`app/storage.py`）：`sessions / results / tool_logs / export_records` 四表，仅作验收证据，不参与核心生成流程；同一会话重试成功后仅保留一条成功导出记录（E1 无重复记录要求）。

### 前端（Streamlit，v0.1 为表单式，v0.2 已重构为对话式）

统一搜索框、四个任务提示按钮（点击填模板并锁定任务类型）、结果编辑、工具状态面板、导出/重试、异常提示。

### 测试与验收材料

- `tests/samples/samples.py`：**13 例冻结合成样本**（正常 N1-N6 / 边界 B1-B4 / 异常 E1-E2 / 路由边界 T4），其中 N1/B1/E1/T4 输入取自评测计划 §4.1 原文，标准答案为手工编写。
- 20 个 pytest 全部通过，覆盖：
  - T1 正常（6/6 全对，超阈值 ≥5/6）；
  - T2 边界（缺失字段标"待确认"、不编造）；
  - T3/E1 导出失败提示、内容保留、重试成功、无重复导出记录与文件；
  - T4 正文含"周报"不误路由，任务类型保持 meeting_minutes；
  - E2 空输入 400 阻止；
  - 零编造校验（编造负责人/日期回退）；
  - Q-02 导出显式触发（generate 不产生导出记录）；
  - 路由：显式锁定、指令区关键词、正文关键词不触发、降级追问、非法 task_type 拒绝；
  - 占位 Skill 返回 P1。
