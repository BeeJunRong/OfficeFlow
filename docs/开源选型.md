# OfficeFlow 核心任务提取与开源选型报告

**版本：v1.0**
**日期：2026-10-13**
**目的**：把 OfficeFlow 的核心内容/任务抽干净，再从 GitHub 上挑出**成熟、维护活跃、真正免费**的开源项目来复用，而不是继续从零手写。
**数据来源**：GitHub REST API（`api.github.com/repos/...`）与各项目官方许可证/文档页面，抓取时间 2026-10-13。凡未实测的数字均标注来源，"未能核实"即未核实。

---

## 一、核心内容/任务提取

### 1.1 一句话定义

> **OfficeFlow = 把一段杂乱的办公原始文本，变成"可核对、可编辑、可导出"的结构化文档。**
> 首版唯一真做的就是：**粘会议记录 → 结构化纪要（日期/主题/决定/待办）→ 人工核对 → 显式导出 .md**。

### 1.2 任务拆成 7 个可独立替换的技术能力

| # | 能力 | 具体做什么 | 现状（自研） | 是否值得找开源 |
|---|------|-----------|-------------|---------------|
| C1 | **意图路由** | 显式点击优先 → 指令区关键词 → LLM 分类兜底，置信度 <0.7 追问 | `app/router.py`（分层正则 + LLM 兜底） | 可复用（分类器节点） |
| C2 | **结构化抽取** | 从中文会议正文抠出 会议日期/主题/决定[]/待办[{事项,负责人,截止日期}] | `app/tools/extract_fields.py`（12KB，手写规则 + LLM） | **最值得复用** |
| C3 | **零编造校验（护城河）** | 原文没有的负责人/日期强制回退"待确认"；每条待办留原文证据片段 | `app/validate.py`（3.3KB，自研） | **有现成库，见 LangExtract** |
| C4 | **渲染与导出** | 结构化 → Markdown → 落盘 .md，失败可重试且不重复记录 | `app/tools/export_markdown.py` | 部分可复用 |
| C5 | **工作流编排** | route → extract → validate → render → export，节点可观测、失败可重试 | `app/graph.py`（LangGraph，3.4KB） | 可复用（但要权衡） |
| C6 | **交互界面** | 统一搜索框 + 4 提示按钮 + 结果编辑 + 工具状态面板 | `frontend/app.py`（Streamlit，10.5KB） | 部分可复用 |
| C7 | **工具调用日志** | 每次调用记 tool_name/status/error/timestamp，作为验收证据 | `app/storage.py`（SQLite，6.3KB） | 平台自带 |

### 1.3 真正的胜负手，其实只有 C2 + C3

C1/C4/C5/C6/C7 都是**工程脚手架**，谁写都差不多，也不影响验收结论。
**C2 + C3 才是这个项目的全部含金量**，因为验收硬门槛全部压在这里：

- 6 例正常样本 ≥5 例关键字段全对；
- 4 例边界样本 ≥3 例正确标"待确认"；
- **所有已输出样本不得捏造明确的负责人或截止日期**（零编造，100% 满足）；
- 每条关键待办要能**回看原文证据**。

> **结论：选型应该优先买"零编造 + 原文可定位"，而不是优先买"更好看的编排平台"。**
> 现在把最多人力花在 `extract_fields.py` 的手写规则上，是投入产出比最低的做法。

### 1.4 硬约束清单（选型必须逐条过）

| 约束 | 内容 | 对选型的影响 |
|------|------|-------------|
| 免费 | 软件许可免费、可自部署 | 排除一切需要商业授权的组件 |
| 中文优先 | ≤4000 汉字输入 | 排除中文支持差的抽取库 |
| 纯文本入口 | **不接收音频**，语音转写明确排除 | 排除所有以 Whisper/FunASR 为核心的会议系统 |
| 零编造 | 缺失字段 ="待确认"，不得臆造 | 需要能给出**证据定位**的抽取方案 |
| 显式导出 | 未经点击不得导出；邮件不自动发送 | 不能选"自动执行副作用"型 Agent 平台 |
| 异常可重试 | 保留内容、无重复记录 | 需要可控重试 + 日志 |
| 可验收 | 工具日志可查、结果可截图 | 需要可视化证据产物 |
| P95 ≤20s | 4000 汉字输入 | 不要引入过重的多跳 Agent 链路 |

### 1.5 一句话给团队

**现状**：核心闭环已经跑通，但 C2 靠手写规则硬扛中文抽取，C3 是几十行自研校验，**这两处是最大风险点，也是开源能立刻救回来的地方**。

### 第 5 层：成本 —— "免费"到底免到什么程度

- 软件许可：上面推荐的 **LangExtract / Instructor / MarkItDown / Docling 全部是 Apache-2.0 或 MIT**，Dify 单租户自用也免费。**软件侧 0 元。**
- 模型调用（唯一的可能开销）：[DeepSeek 官方定价](https://api-docs.deepseek.com/quick_start/pricing) `deepseek-flash` 缓存未命中输入 $0.15/百万token、输出 $0.60/百万token（低谷价，高峰翻倍）。
  按 4000 汉字输入 ≈ 3–4k token、输出 ≈ 1.5k token 估算，**单次生成不到 0.001 美元**，跑完全部 13 例样本的总花费**不足 1 分钱人民币**。
- 想做到**字面意义上 0 元**：走项目已支持的 Ollama 本地模型（`OFFICEFLOW_MODEL_BASE_URL` 指向本地），LangExtract 与 Instructor 都原生支持 Ollama。

## 三、推荐方案

### 方案 A（推荐）：保留现有骨架，用 LangExtract 换掉最脆弱的 C2/C3

```text
Streamlit 前端（保留，C6）
   ↓
FastAPI（保留，C4/C7）
   ↓
LangGraph 编排（保留，C5）
   ↓
【新】LangExtract 抽取节点  ← 替换 extract_fields.py 的手写规则
   · extraction_class: decision / action_item / meeting_date / topic
   · 每条结果带 char_interval → 原文证据自动可得（C3 从"自研校验"变"库保证"）
   · OpenAI 兼容端点直连现有 DeepSeek 配置，或 Ollama 本地跑
   · 输出交互式 HTML → 直接当"原文依据可回看"的验收证据
   ↓
validate.py 只保留"业务口径"（缺失 → 待确认）  ← 逻辑从 3.3KB 缩到几十行
```

**为什么选它**：
1. 直接命中项目唯一硬门槛（零编造 + 原文依据），且是**库层面保证**而非自研规则；
2. Apache-2.0，无商业限制，可本地可云端；
3. 改动是**增量的**：现有 13 例测试与 API 契约全部不用动，风险最低；
4. 顺带白拿一个可视化证据产物，直接服务于"验收证据保存"。

**代价**：抽取质量取决于 prompt 与 few-shot 示例，需要重新调一轮；团队要花半天读它的 few-shot 范式。

### 方案 B：彻底搬到 Dify 可视化工作流（演示效果最好，成本最高）

用 Dify 的问题分类器（C1）+ LLM 节点（C2）+ 代码节点（C3）+ 节点重试与日志（C7）+ 自带 Web UI（C6），**自研代码量可压到只剩一个校验代码节点**。
适合"想拿一个漂亮可视化流程去答辩"的场景；但等于推翻现有 LangGraph 与 Streamlit 实现，且 Dify 的修改版许可证需要团队写进合规说明。

### 方案 C：只做最小补丁（如果时间极紧）

现有代码不动，只接一个 LangExtract 调用替换 `extract_fields.py` 的 LLM 分支（规则分支继续作为离线降级），其余全部保留。半天到一天可完成。

**建议**：以 **A** 为基线推进；若答辩需要视觉冲击，再把 Dify 作为"编排层演示"叠加（B 的界面部分可以只用于演示，不影响后端）。

## 四、明确不建议做的事

1. **不要把语音转写（Whisper/FunASR）引进来**——已在 proposal §5 明确排除，引进来会直接破坏范围与验收边界。
2. **不要选 Flowise**——仓库已归档。
3. **不要把 coze-studio 当主线**——近 3 个月无提交，维护风险高。
4. **不要为了"全开源"而放弃自研 C3 的业务口径**——"缺失字段统一显示待确认"是本项目的产品定义，不是通用能力，任何库都不会替你做。
5. **不要引入多智能体框架**——proposal §5 已排除"多智能体自治协作"，且会直接威胁 Q-01 的 P95 ≤20s。

## 附：核验说明与残留风险

**已逐条核验（2026-10-13，数据取自 api.github.com 与各仓库 LICENSE 原文）**：本报告中所有 star / 最近 push / 许可证名称与附加条款要点，均为实际抓取结果，无记忆值。逐条核验的 8 个仓库（LangExtract、Instructor、Dify、Open WebUI、LobeHub、MarkItDown、Docling、LibreChat）`archived` 全部为 `false`；唯一归档的是 Flowise（已排除）。

**残留风险**：

- LangExtract 在**中文**会议文本上的抽取质量需用本项目 13 例样本实测，官方示例均为英文。
- `agentkit-ui`（architecture.md §2 提到的 React 前端）：GitHub `bytedance/AgentKit` **返回 404**，npm 上查到的是第三方 `@polycrestlabs/agentkit-ui`，**未核实存在对应的官方开源项目**，不建议据此排期。

- LangExtract 依赖链较重（`pandas`/`numpy`/`google-genai` 等），若团队想保持 `requirements.txt` 精简，Instructor 是更小的替代。
