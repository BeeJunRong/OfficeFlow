# OfficeFlow FR-01 评测计划报告

**版本：v1.2**

**日期：2026-10-16**

本次新增 §12 输入框交互回归，其余 FR-01 业务验收基线保留。FR-02～FR-04 的完整业务验收仍不属于本计划范围；§12 覆盖其共用输入入口。

## 1. 测试目标

验证 FR-01 在正常、差异/边界、异常、路由边界场景下是否满足任务单规定的可观察结果与通过阈值。

## 2. 测试范围

- **包含**：FR-01 会议纪要生成、结构化字段抽取、缺失值处理、Markdown 导出、异常重试、Skill 路由边界。  
- **不包含**：FR-02 周报整理、FR-03 邮件草稿、FR-04 网页整理的完整生成；自动发送邮件；批量爬取。

## 3. 测试环境

- 同一台开发测试电脑  
- 同一模型与版本  
- 稳定网络，无其他并发任务  
- 测试环境注入受控错误（仅测试环境）  
- 记录浏览器时间戳和原始耗时

## 4. 测试样本

样本规模：13 例（正常 6、差异/边界 4、异常 2、路由边界 1）。  
固定样本及正确结果来源：本组手工编写并复核的“合成会议文本 + 标准字段答案”，不使用未核验的 AI 输出作标准答案。

## 5. 测试步骤

1. 冻结测试输入与标准答案。  
2. 运行系统。  
3. 截图输入、生成结果、任务类型标识和工具调用状态。  
4. 保存导出的 .md 或报错截图。  
5. 逐字段对照预先标注的标准答案。  
6. 在验收表记录通过/不通过及原因。

## 6. 通过阈值（团队拟定）

| 类别 | 样本数 | 通过要求 |
|------|--------|----------|
| 正常 | 6 | ≥5 例全部关键字段正确 |
| 差异/边界 | 4 | ≥3 例正确标注缺失字段 |
| 异常 | 2 | 全部正确提示且不丢内容 |
| 路由边界 | 1 | 不误路由 |
| 零编造 | 所有 | 不得捏造明确的负责人或截止日期 |

未达到任一项，FR-01 不通过。

数字来源：13 例、5/6、3/4、2/2、1/1 及“零编造”均为【团队拟承诺的验收门槛】，非外部标准、非实测结论。

## 7. 判定人与分工

- 由非 FR-01 开发成员的组员执行测试；本组 3 人均参与 FR-01 开发，故首轮验收建议由邻组执行。  
- 本组内部由张敏杰组织、马浚荣与曾加健交叉复核。  
- 最终可请邻组按同一说明重复验收。

## 8. 证据保存

- 截图：输入、生成结果、任务类型标识、工具调用状态。  
- 文件：导出的 .md 或报错截图。  
- 记录：验收表，逐字段记录通过/不通过及原因。  
- 工具日志：工具调用名称、状态、错误信息、时间戳。

## 9. 性能测试（Q-01）

- 指标：≤4,000 汉字输入，从点击“↑”发送按钮或按 Enter 提交到页面完整显示可编辑结果，测量 20 次，P95 ≤20 秒。
- 条件：同一台开发测试电脑、同一模型与版本、稳定网络、无其他并发任务。  
- 记录：浏览器时间戳和原始耗时。  
- 模型或网络不可用时不计入正常性能样本，单独进行故障测试。  
- 来源：团队拟定目标，待原型测试后确认。

## 10. 路由准确性测试（Q-03）

- 显式点击路径：任务类型识别准确率 100%。  
- 直接输入路径：会议纪要意图识别 ≥90%（10 例中 ≥9 例正确路由或追问）。  
- 测量方式：用 10 例含不同表述的直接输入样本测试，记录路由结果与期望任务类型。  
- 若 LLM 意图分类不稳定，降级为“直接输入路径提示用户选择任务类型”。  
- 来源：团队拟定目标，非实测结论。

## 11. 风险与应对

| 风险 | 应对 |
|------|------|
| LLM 编造日期 | Pydantic 校验 + 规则引擎回退“待确认” |
| 导出工具失败 | 注入受控错误，验证提示、保留、重试 |
| 路由误判 | 显式点击优先；LLM 低置信度追问；降级方案 |
| 免费 API 额度不足 | 本地 Ollama 快速迭代，正式验收切换云端 |
| 性能不达标 | 早期计时，调整模型或目标值 |

## 12. 输入框交互与过渡回归（FR-05）

### 12.1 浏览器验收

启动本地前后端，分别在桌面宽度和约 390 px 窄屏验证。过渡检查应观察发送前、动画中、处理中及结果返回全过程，必要时录屏逐帧复核。

| 编号 | 操作 | 验收标准 |
|------|------|----------|
| UI-01 | 打开无历史对话的页面；输入空格后再输入多行内容 | 输入框居中；空白内容禁用发送，有内容高亮；高度自适应，达到上限后框内滚动；底栏标签左、发送按钮右 |
| UI-02 | 点击任务标签，再在已有内容时切换标签；选择“自动识别” | 空内容时填入对应提示词；已有材料不被覆盖；选中标签可见；发送时显式任务类型生效，自动识别清除显式选择 |
| UI-03 | 使用 Shift + Enter、Enter 和中文输入法组词回车 | Shift + Enter 仅换行；Enter 发送；组词确认不误发送；发送立即清空输入，处理中阻止重复提交 |
| UI-04 | 从居中状态首次发送，并等待结果返回 | 同一输入框持续可见，通过 transform 平滑移到底部；无卸载重建、闪烁、消失或位置回弹；结果返回不触发第二次定位动画 |
| UI-05 | 连续发送至少 3 条，滚动查看消息末尾，再点击“新建对话” | 每次发送始终使用同一组件且保持底部位置；消息列表不挤压输入框，末尾内容能滚动到可见区域；新建对话清空历史、任务和草稿，组件回到初始位置 |
| UI-06 | 在窄屏滚动任务标签；系统开启减少动态效果后复核 | 标签横向滚动，发送按钮始终可见且不被挤压；减少动态效果时不播放过渡，但输入框仍持续挂载 |

### 12.2 自动化回归与证据边界

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_composer.py -q
node --test tests/frontend/composer.test.mjs
```

- `test_composer.py`：检查只有一个输入组件；无对话、1 轮、3 轮及新建对话后，组件 ID 和 Streamlit 渲染树位置一致。
- `composer.test.mjs`：模拟连续三次发送，检查本地清空先于 Python 通知、动画帧顺序、标签 DOM 复用、禁用/恢复、草稿保留和新对话复位。
- 2026-10-16 实测：Python 全量 **75 passed**，JavaScript **1 passed**；浏览器观察首条发送、返回结果及第二次发送，输入框节点保持不变。
- 自动化测试验证结构和时序，不覆盖真实浏览器逐帧动画、全部窄屏与输入法场景。完整 UI-01～UI-06 验收需另行记录浏览器版本、视口、操作及截图或录屏，不将上述测试数量等同于完整视觉验收通过。
