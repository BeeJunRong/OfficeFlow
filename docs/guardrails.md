# OfficeFlow 护栏与安全约束（Guardsrails）

**版本：v1.4.0**
**日期：2026-10-14**

本文件定义首版必须遵守的行为边界、安全约束与失败处理规则。所有约束均来自任务单 v1.1，数字为团队拟定门槛，非实测结论。

> **v1.4.0 变更说明（需团队确认）**：FR-03 邮件草稿增加了"发送协议"能力。
> 为不破坏 Q-02，**默认路径仍是"只出草稿、绝不发送"**；
> 真实发送是**显式选择 + 显式确认**的可选能力，且需要运维在 .env 中二次开启总开关。
> 详见 §1.1。若团队决定不引入任何真实发送能力，把
> `OFFICEFLOW_EMAIL_ENABLE_SEND` 保持为 0 即可回到原语义。

## 1. 安全与可控（Q-02，必须 100% 满足）

- **只生成邮件草稿，不自动发送**：生成流程（`/api/generate`、`/api/derive`）**绝不**调用任何发送逻辑。  
- **导出以用户显式点击为触发**：未经用户点击“导出 .md”，不得自动导出或上传文件。  
- **不可逆行为人工确认**：发送、对外分享等操作不由 Agent 擅自执行。  
- **工具调用日志可查**：记录每次工具调用的名称、状态、错误信息、时间戳，用于验收核查。

### 1.1 邮件发送协议（FR-03，v1.4.0 新增）

协议是**显式字段**，默认 `draft_only`：

| 协议 | 行为 | 是否产生网络发送 | 默认 |
|------|------|------------------|------|
| `draft_only` | 只返回预览；可复制内容、导出 `.md` | ❌ 从不 | ✅ |
| `mailto` | 生成 `mailto:` 链接，由**用户本机邮件客户端**完成发送 | ❌ 服务端不发送 | — |
| `smtp` | 服务端直发 | ✅ 仅在四重闸门同时满足时 | — |

`smtp` 真实发送的**四重闸门**（缺一不发，且每一道都会在界面明确提示原因）：

1. 用户在界面**显式点击**操作按钮（不是生成流程的一部分）；
2. 请求带 `confirm=true`；
3. `.env` 中 SMTP 配置齐全（`OFFICEFLOW_SMTP_HOST/USER/PASSWORD/FROM`）；
4. `.env` 中 `OFFICEFLOW_EMAIL_ENABLE_SEND=1`（**防误发的总开关，默认 0**）。

其他不可协商的约束：

- **邮箱地址一律由用户手动填写**。系统**绝不**推测或拼接邮箱（如"张三"→`zhangsan@…` 属编造）。
- 未勾选"发送这封"的收件人**不会被处理**（默认全部不勾选）。
- 任一闸门未满足时，返回 `dry_run=true` 且状态为 `preview`/`failed`，**绝不谎报"已发送"**。
- 发送结果逐封返回 `sent / preview / skipped / failed`，便于逐封核对。

## 2. 缺失值与零编造规则

- 只提取原文明确出现的决定、待办、负责人和日期。  
- 原文未提供的字段统一显示“待确认”，不得编造。  
- 时间信息可按明确年月日标准化（如“10月12日”结合会议日期标准化为“2026-10-12”）。  
- 每条关键待办附可回看原文的简短证据片段或定位信息。  
- **零编造检查**：若原文无日期但输出具体日期，系统必须回退为“待确认”。  
- 验收时，所有已输出样本中不得捏造明确的负责人或截止日期。

## 3. Skill 路由规则（FR-00）

- **显式点击优先**：用户点击“会议纪要”提示按钮，锁定 `task_type=meeting_minutes`，不再看正文关键词。  
- **指令区关键词快速匹配**：只检查输入开头或冒号前的短指令。  
- **LLM 意图分类兜底**：置信度低于 0.7 时追问用户，不静默路由。  
- **正文关键词不触发路由**：正文中的“周报”“邮件”只作为内容，不作为任务类型依据。  
- **纯关键词路由不采用**：避免会议原文中“下周周报由李四负责”导致误路由。  
- **Q-03 路由准确性**：显式点击路径 100% 准确；直接输入路径会议纪要意图识别 ≥90%（10 例中 ≥9 例正确路由或追问）。若 LLM 分类不稳定，降级为“直接输入路径提示用户选择任务类型”。

## 4. 异常处理与恢复

- **空输入**：阻止生成，提示用户输入非空会议文字记录。  
- **工具失败**：明确报错，说明失败步骤，保留已输入/已生成内容，支持重试。  
- **导出失败**：提示“导出失败，可重试”，不得声称导出成功；页面原始输入、生成结果和用户修改内容仍在；恢复后可成功导出，且不出现重复导出记录。  
- **模型/网络不可用**：不计入正常性能样本，单独进行故障测试；向用户展示可恢复操作。

## 5. 性能约束（Q-01）

- 对 ≤4,000 汉字会议输入，从点击“↑”发送按钮或按 Enter 提交到页面完整显示可编辑结果，测量 20 次，P95 ≤20 秒。
- 测试条件：同一台开发测试电脑、同一模型与版本、稳定网络、无其他并发任务。  
- 记录浏览器时间戳和原始耗时。  
- 该目标为团队拟定，待原型测试后确认。

## 6. 人工核查

- 用户必须检查责任人、时间、事实依据，纠错后再导出。  
- 验收时由非 FR-01 开发成员的组员执行测试，另请邻组重复验收。  
- 本组 3 人均参与 FR-01 开发，故首轮验收建议由邻组执行；本组内部由张敏杰组织、马浚荣与曾加健交叉复核。  
- 证据保存：截图输入、生成结果、任务类型标识、工具调用状态；保存导出的 .md 或报错截图；逐字段对照标准答案。

## 7. 排除项（首版不做）

- 语音转写、批量网站爬取、需要登录的网页  
- 自动发送邮件（生成流程绝不发送；smtp 需用户显式点击 + 四重闸门，默认 draft_only）、自动发布周报、跨账号权限管理  
- 多智能体自治协作、准确率未经测试的承诺  
- 纯关键词路由
