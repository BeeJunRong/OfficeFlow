## 3. 启动流程

### 方式一：一键脚本（推荐）

```powershell
# 启动后端(8000) + 前端(8501)，各自独立窗口
.\scripts\start.ps1 start

# 查看状态
.\scripts\start.ps1 status

# 停止全部
.\scripts\start.ps1 stop

# 单独启动
.\scripts\start.ps1 start-backend
.\scripts\start.ps1 start-frontend
```

脚本会：检查 `.venv` 是否存在 → 检查端口占用 → 后台拉起进程 → 记录 PID 到 `.run\`。

### 方式二：手动开两个终端

**终端 1 —— 后端（端口 8000）**

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 即成功。

**终端 2 —— 前端（端口 8501）**

```powershell
.\.venv\Scripts\python.exe -m streamlit run frontend\app.py --server.port 8501
```

浏览器会自动打开 <http://localhost:8501>；若没打开，手动访问该地址。

> 两个终端都不能关。关掉终端 = 关闭服务。

### 启动顺序

**先后端，后前端。** 前端启动时会去连 `OFFICEFLOW_BACKEND`，后端没起来会显示连接失败。

### 验证清单

| 检查 | 命令 / 地址 | 期望 |
|------|-------------|------|
| 后端存活 | <http://127.0.0.1:8000/docs> | 出现 FastAPI 接口文档页 |
| 后端健康 | <http://127.0.0.1:8000/api/status/test> | 返回 JSON（不报 500） |
| 前端存活 | <http://localhost:8501> | 出现居中搜索框 + 4 个提示按钮 |
| 端到端 | 点「会议纪要」→ 粘一段会议记录 → 生成 → 导出 .md | 结构化结果 + 下载文件 |

## 4. 部署后自检（LangExtract）

装完 LangExtract 后，先跑自检脚本，再决定是否启用：

```powershell
# 步骤 1-3：依赖 / 中文分词 / 配置
.\.venv\Scripts\python.exe scripts\check_langextract.py

# 含步骤 4：用 N1 样本真实调用模型，打印 char_interval 与切出的证据
.\.venv\Scripts\python.exe scripts\check_langextract.py --live
.\.venv\Scripts\python.exe scripts\check_langextract.py --live --sample B1
```

自检脚本会重点验证一件事：**中文必须用 `UnicodeTokenizer`。**
LangExtract 默认的 `RegexTokenizer` 把连续的汉字视为**一个** token（其词模式是 `[^\W\d_]+`），
对中文做"抽取结果回贴原文"的对齐时会直接失效。`UnicodeTokenizer` 对 CJK 逐字成 token，
并把 `。！？` 识别为句末，中文场景必须显式传入——本项目已在
`app/tools/langextract_extract.py` 中固定传入。

### 启用 LangExtract 抽取路径

```powershell
# .env 中追加
OFFICEFLOW_LANGEXTRACT_ENABLE=1
```

未启用时，抽取走原有 `app/tools/extract_fields.py`（LLM 分支 + 规则降级），行为完全不变。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| **`ModuleNotFoundError: No module named 'app.env'; 'app' is not a package`** | `frontend/app.py` 自身被注册为顶层模块 `app`，脚本内 `from app.xxx import` 会解析到自己 | 前端入口**禁止导入 `app` 包**，只用 `frontend/env_loader.py`（纯标准库）。见 §8 缺陷 3 |
| **`RecursionError: maximum recursion depth exceeded`（栈里反复出现 frontend/app.py）** | 同上；若中途删 `sys.modules['app']` 触发重新查找，会重新执行脚本自身 | 同上。**不要**用删缓存项的方式修补这个导入 |
| `conda : 无法将"conda"项识别为 cmdlet` | 本机没装 conda | 改用 `.venv\Scripts\python.exe`，见 §1 |
| `ModuleNotFoundError: No module named 'app'` | 不在项目根目录启动 | `cd` 到项目根目录再执行 |
| 生成的负责人/日期总是"待确认" | **没有配置 API Key**，走了规则引擎 | 检查 `.env` 或 `$env:OFFICEFLOW_MODEL_API_KEY` |
| 前端提示连不上后端 | 后端没起 / 端口不是 8000 | 先启后端；或改 `OFFICEFLOW_BACKEND` |
| `Address already in use` | 8000/8501 被占用 | `.\scripts\start.ps1 status` 查占用，再 `stop` |
| 导出失败 | 导出目录不可写 | 检查 `OFFICEFLOW_EXPORT_DIR`，页面内容不会丢，可重试 |
| `pip install` 报 "Access is denied" | 沙箱/权限拦截了 site-packages 写入 | 用管理员 PowerShell，或确认无安全软件锁目录 |
| **PowerShell 脚本报 "Missing closing '}'"** | 用 Windows PowerShell 5.1 运行**无 BOM** 的含中文 `.ps1`，汉字被按 GBK 解码，尾字节变成伪 `}` | 用 VS Code「UTF-8 with BOM」重存；本仓库 `scripts\start.ps1` 已存为带 BOM |
| 中文输出乱码 | 控制台编码不是 UTF-8 | `scripts\start.ps1` 已内置设置；手动运行时先 `chcp 65001` 或设 `$env:PYTHONIOENCODING='utf-8'` |

### 部署过程中发现并修复的两个既有缺陷

1. **`.env` 完全不生效**（部署前）：`app/storage.py`、`frontend/app.py`、`app/llm.py` 都读环境变量，
   但全项目没有 dotenv 加载逻辑，因此写 `.env` 是无效的。
   → 新增 `app/env.py`，并在 `app/main.py`、`frontend/app.py` 的**业务 import 之前**调用 `load_env()`。
   特性：已存在的进程环境变量优先（便于临时覆盖）；未装 python-dotenv 时静默跳过、不阻断启动。

2. **中文 `.ps1` 在 PowerShell 5.1 下无法解析**（编写启动脚本时踩到）：
   无 BOM 的 UTF-8 文件被按 GBK 解码，汉字尾字节产生伪 `}`、吃掉字符串结尾引号，报
   "Missing closing '}'"，但**大括号实际是配平的**。
   → `scripts\start.ps1` 已保存为 **UTF-8 with BOM**，并在脚本内设置控制台 UTF-8。

3. **前端入口与 `app` 包同名导致的自导入**（用户实测报出，经历两次错误修复）：
   `frontend/app.py` 会被 Python/Streamlit 注册为顶层模块 `app`，因此该文件内任何
   `from app.xxx import ...` 都解析到**脚本自身**：

   - 第一版修补（删 `sys.modules['app']` 再导入）**反而更糟**：重新查找时又命中
     `frontend/app.py` 并从头执行 → `RecursionError: maximum recursion depth exceeded`。
   - **正确解法**：前端入口不导入 `app` 包。新增 `frontend/env_loader.py`（纯标准库解析
     `.env`，行为与 `app/env.py` 一致：进程环境变量优先），`frontend/app.py` 只导入它。

   ⚠️ **教训**：这三次问题（`app.env` 导入失败、递归、路由误判）中，前两个是靠
   **Streamlit AppTest 查不出来的**——AppTest 与 `streamlit run` 的模块加载方式不同。
   凡改动 `frontend/app.py` 的导入，必须用 `streamlit run` 真实启动一次验证，不能只跑 AppTest。

## 9. 关键约束提醒（别在部署时破坏）

- **只生成邮件草稿，绝不自动发送；导出必须由用户点击触发**（Q-02，必须 100% 满足）。
- **零编造**：原文缺失的负责人/日期一律显示"待确认"，不得编造。
- **不引入语音转写**：语音转写已在需求中明确排除，不要因为"会议"二字就去接 Whisper。
- LangExtract 启用后，`char_interval` 为 `None` 的抽取会被**直接丢弃**，这是零编造约束的落点，
  不要为了"结果更多"而放宽它。
